# 文献搜索端到端验收清单

## 前置条件

1. 当前项目解释器已安装根目录 `requirements.txt` 中的依赖。
2. 本地 `.env` 已配置可用的 OpenAlex 密钥；需要 Semantic Scholar 时再启用其 Key 与开关。
3. Redis 是可选项：未启用或不可用时，搜索仍应通过 SQLite 和进程内回退路径完成。
4. 由操作者在仓库根目录启动后端，在 `frontend/` 启动前端；本清单不要求或暗示自动调用真实外部 API。

## 离线回归

先运行下列只使用 mock、替身或 SQLite 临时状态的测试：

```powershell
pytest backend/tests/test_multi_source_search_api.py backend/tests/test_search_result_page_api.py backend/tests/test_paper_detail_api.py backend/tests/test_compare_api.py backend/tests/test_citation_graph_api.py backend/tests/test_technical_routes_api.py backend/tests/test_usage_api.py backend/tests/test_search_run_history_api.py
```

在 `frontend/` 运行：

```powershell
npm test
npm run build
```

## 手动验收路径

使用一个小规模、可公开检索的主题，按顺序确认：

1. 提交自然语言查询，页面先收到 `run_created`，再持续显示节点、轮次或降级事件，最后收到终态事件。
2. 首个事件中的 `run_id` 出现在浏览器地址；搜索进行中刷新页面，页面读取运行状态而不重复创建搜索。
3. 终态后确认论文列表、来源与核验状态可见；修改来源、年份和排序后，分页结果来自同一 `run_id`，不重新检索。
4. 打开任一论文详情；选择 2 至 5 篇论文比较；打开引用图与技术路线，确认它们只反映当前已保存结果。
5. 确认实际用量面板与搜索历史可读；恢复一条终态历史记录；显式清理一条终态记录，并确认运行中记录不会被清理。
6. 关闭或禁用 Redis 后重复一次小规模查询，确认搜索可完成；启用 Redis 后确认健康接口报告可用状态且不会改变最终论文结果契约。

## 通过标准与记录

- 记录 `run_id`、时间、是否启用 Redis、选用来源、终态状态、停止原因和任一降级来源。
- 不在截图、日志或问题报告中包含 API Key、完整敏感查询、完整外部原始响应或受限全文。
- 任一步失败时，保留 `run_id` 与浏览器控制台的安全错误摘要，用于后续定位，不重复提交同一高成本查询。

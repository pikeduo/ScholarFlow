# 阶段四：规范化去重与多源融合

## 1. 阶段目标

本阶段将阶段二输出的多来源候选转换为统一 `PaperRecord`，完成字段规范化、来源追踪、身份解析、版本族管理、确定性过滤、RRF 融合和 SQLite 持久化。

完成后，系统应能够稳定回答：

- 不同来源的两条记录是否是同一篇论文。
- arXiv 预印本、会议版和期刊版是否属于同一工作族。
- 某个字段来自哪个来源。
- 某条记录为什么被过滤、合并或保留。
- 多来源排名如何融合为一个可复现分数。

---

## 2. 前置条件

- 阶段二能返回 `SourcePaperRecord`。
- 阶段三已建立 `normalize_merge` 和 `deduplicate_fuse` 节点。
- SQLite 基础 Repository 和 Alembic 可用。
- QueryIntent 已稳定。

## 4. 小阶段 4.1：PaperRecord 领域模型

建议定义：

```python
class PaperIdentifier(BaseModel):
    scheme: str
    value: str
    normalized_value: str
    source: str

class AuthorRecord(BaseModel):
    name: str
    normalized_name: str
    orcid: str | None
    source_ids: dict[str, str]
    position: int

class SourceProvenance(BaseModel):
    source: str
    external_id: str
    source_rank: int | None
    matched_subquery: str | None
    fetched_at: datetime
    fields_present: list[str]

class PaperRecord(BaseModel):
    paper_id: str
    title: str
    normalized_title: str
    abstract: str | None
    abstract_source: str | None
    keywords: list[str]
    authors: list[AuthorRecord]
    first_public_year: int | None
    publication_year: int | None
    venue: str | None
    normalized_venue: str | None
    paper_type: str | None
    identifiers: list[PaperIdentifier]
    open_access_url: str | None
    cited_by_count: int | None
    provenance: list[SourceProvenance]
    work_family_id: str | None
    metadata_quality: float
    created_at: datetime
    updated_at: datetime
```

内部 `paper_id` 一旦持久化应保持稳定，不使用某一来源 ID 作为主键。

## 5. 小阶段 4.2：标识符规范化

### 5.1 DOI

处理顺序：

1. Unicode NFKC。
2. 去首尾空格。
3. 转小写。
4. 移除 `https://doi.org/`、`http://dx.doi.org/`、`doi:`。
5. 去尾部句号、逗号、右括号等文本标点。
6. 使用保守正则校验。

输出：

```python
class NormalizedIdentifierResult(BaseModel):
    raw_value: str
    normalized_value: str | None
    valid: bool
    reason: str | None
```

非法 DOI 不直接删除，保留原值用于诊断，但不能作为强去重键。

### 5.2 arXiv ID

- 统一新旧格式。
- 分离版本号，例如 `v2`。
- 去 URL 前缀。
- 基础 arXiv ID 用于论文身份，版本号用于版本信息。

### 5.3 PMID、OpenAlex、S2、DBLP

- 去来源 URL 前缀。
- 统一大小写策略。
- 保存 scheme。
- 对明显不合法格式标记无效。

---

## 6. 小阶段 4.3：标题规范化

### 6.1 规范化步骤

- Unicode NFKC。
- 转小写。
- HTML 实体解码。
- 合并空白和换行。
- 标准化连字符和引号。
- 去除不影响语义的首尾标点。
- 保留字母、数字和必要数学符号。

### 6.2 指纹

生成多个指纹：

- `strict_title_hash`：规范化全文哈希。
- `token_title_hash`：去停用词后的 token 哈希。
- `title_prefix_hash`：用于阻塞候选对。

标题规范化结果不能覆盖前端展示的原始标题。

---

## 7. 小阶段 4.4：作者规范化

### 7.1 字段

- 原始姓名。
- 规范化姓名。
- ORCID。
- 来源作者 ID。
- 作者顺序。

### 7.2 规则

- Unicode NFKC。
- 合并空格。
- 姓名大小写规范只用于比较。
- 不随意调整东亚姓名顺序。
- 有 ORCID 或平台 ID 时优先。
- 仅凭缩写相同不能判定同一作者。

### 7.3 第一作者匹配

缺少强标识符时，标题、年份和第一作者组合用于生成候选对，但不能单独作为最终合并依据。

---

## 8. 小阶段 4.5：venue 与年份规范化

### 8.1 venue

建立别名表：

```text
NeurIPS ↔ Advances in Neural Information Processing Systems
ICML ↔ International Conference on Machine Learning
```

保存：

- 原始 venue。
- 规范化 venue。
- venue 类型。
- 来源。

### 8.2 年份

区分：

- `first_public_year`：首次公开年份，常对应预印本。
- `publication_year`：正式发表年份。

用户“近五年”默认使用正式发表年份；没有正式年份时可回退首次公开年份，并在结果中标注。

---

## 9. 小阶段 4.6：摘要和元数据冲突

### 9.1 摘要选择

优先级可配置，例如：

1. 内容完整、非截断摘要。
2. 更新时间较新。
3. 来源可靠性。

不能静默覆盖冲突摘要，应保存 `abstract_source` 和必要的 source snapshot。

### 9.2 引用数

不同来源统计口径不同：

- 不合并为绝对真值。
- 可保存各来源引用数。
- canonical `cited_by_count` 使用配置规则选择主值。
- 前端可显示来源说明。

## 10. 小阶段 4.7：来源追踪

每个 canonical 论文保存 `provenance`：

- 来源。
- 外部 ID。
- 原始排名。
- 命中子查询。
- 抓取时间。
- 提供的字段。
- 原始数据版本。

数据库建议：

```text
papers
paper_identifiers
paper_sources
paper_field_values      # 可选，用于冲突字段审计
```

任何推荐结果都必须能反查到来源记录。

---

## 11. 小阶段 4.8：候选对生成

不能对 N 条记录执行全量 O(N²) 比较。先进行 Blocking：

- 相同 DOI。
- 相同 arXiv ID。
- 相同平台映射。
- 相同标题哈希。
- 标题前缀 + 年份。
- 标题 token 哈希 + 第一作者。

只有进入同一 Block 的记录才执行进一步相似比较。

---

## 12. 小阶段 4.9：精确去重

### 12.1 强规则

可直接合并：

- 规范化 DOI 相同。
- 同一来源唯一 ID 相同。
- 明确跨平台映射相同。
- 基础 arXiv ID 相同。

### 12.2 弱规则

需要组合判断：

- 标题高度一致。
- 年份相近。
- 第一作者一致或重叠。
- venue 一致。
- 摘要相似。

### 12.3 判定结果

```python
class IdentityDecision(BaseModel):
    left_id: str
    right_id: str
    decision: Literal["same_record", "same_family", "different", "uncertain"]
    confidence: float
    evidence: list[str]
```

`uncertain` 不自动合并。

## 13. 小阶段 4.10：版本族管理

### 13.1 WorkFamily

```python
class WorkFamily(BaseModel):
    work_family_id: str
    canonical_paper_id: str
    member_paper_ids: list[str]
    relations: list[VersionRelation]
```

### 13.2 关系类型

- `preprint_of`
- `published_version_of`
- `extended_version_of`
- `same_work`
- `unknown_version_relation`

### 13.3 canonical 版本选择

优先：

1. 元数据最完整。
2. 正式期刊或会议版。
3. DOI 可用。
4. 摘要完整。
5. 开放链接合法。

前端默认展示 canonical，但保留所有版本入口。

## 15. 小阶段 4.12：QueryIntent 规则过滤

### 15.1 硬过滤

适合代码确定的条件：

- 年份超范围。
- 明确作者不匹配。
- venue 明确不匹配。
- 论文类型被排除。
- 标题或摘要明确包含 exclude。

### 15.2 不宜硬过滤

- 方法是否真正使用。
- 数据集是否用于实验。
- 论文是否属于某个复杂主题。

这些交给阶段五语义排序和 LLM 核验。

### 15.3 FilterDecision

```python
class FilterDecision(BaseModel):
    paper_id: str
    keep: bool
    hard_failures: list[str]
    soft_warnings: list[str]
    matched_rules: list[str]
```

所有过滤原因写入运行记录。

## 16. 小阶段 4.13：RRF 多源融合

### 16.1 公式

```text
rrf_score(p) = Σ source_weight(s) / (k + rank_s(p))
```

### 16.2 参数

- `k` 配置化。
- 来源权重配置化。
- 同一来源的多个子查询是否累加需要设置上限，避免查询数量多的来源占优。

### 16.3 附加特征

可在 RRF 后保存但不直接混入公式：

- 命中来源数量。
- 命中子查询数量。
- 元数据完整度。
- 是否含摘要。

### 16.4 输出

```python
class FusionScore(BaseModel):
    paper_id: str
    rrf_score: float
    source_contributions: dict[str, float]
    source_ranks: dict[str, list[int]]
```

确保相同输入产生可复现输出。

## 17. 小阶段 4.14：SQLite 数据模型

建议增加：

```text
papers
paper_identifiers
paper_sources
paper_field_values
work_families
work_family_members
paper_relations
search_results
filter_decisions
fusion_scores
```

### 17.1 关键约束

- `paper_identifiers(scheme, normalized_value)` 建唯一索引，但非法或空值不进入唯一约束。
- `paper_sources(source, external_id)` 唯一。
- Work family member 不能同时属于多个冲突族。
- 所有关系使用外键。

### 17.2 Upsert 顺序

1. Upsert identifiers 和来源记录。
2. 查找已有 canonical paper。
3. 新建或更新 paper。
4. Upsert authors 和关联。
5. 写 work family。
6. 写 search result、filter 和 fusion 记录。
7. 提交事务。

## 19. 元数据质量分

建议单独计算 `metadata_quality`：

- 标题存在。
- 摘要存在。
- 作者存在。
- 年份存在。
- venue 存在。
- 至少一个强 ID。
- 来源数量。

质量分仅用于同等相关性下的辅助排序，不能代替主题相关性。

## 20. 测试规划

固定 fixture 覆盖：

- DOI URL 与裸 DOI。
- DOI 尾部标点。
- 同一 arXiv 不同版本。
- arXiv 与 DOI 正式版。
- 标题标点和大小写差异。
- 同标题但不同年份和作者。
- 作者缩写和非 ASCII 姓名。
- venue 全称和缩写。
- 缺摘要。
- 多来源摘要冲突。
- 非法 DOI。
- 版本族不确定。
- RRF 多来源和多子查询。
- 硬过滤和软警告。

### 性质测试

- 规范化函数幂等。
- 合并顺序不改变 canonical 结果。
- RRF 输入顺序不改变得分。
- 同一标识符不会生成两个 canonical paper。

## 21. 性能要求

- 使用 Blocking 避免全量两两比较。
- 规范化和规则过滤可批量执行。
- SQLite 使用批量 Upsert 和短事务。
- 不在本阶段运行 BGE-M3 全量相似去重；仅预留不确定候选接口。
- 记录每个步骤耗时和候选规模。

## 23. 阶段验收条件

- 多来源同一论文合并为稳定 `paper_id`。
- arXiv、会议和期刊版本可进入同一 work family。
- 不确定版本关系不会被强行合并。
- 所有 canonical 字段可追踪来源。
- 每条过滤记录有明确原因。
- RRF 分数和来源贡献可复现。
- 数据库不存在重复强标识符和孤立关系。
- LangGraph 能展示去重前后数量和版本族统计。
- 本阶段未使用 LLM 代替确定性身份解析。

# 阶段七：系统集成与交付

## 1. 阶段目标

本阶段完成 ScholarFlow 的系统集成、可靠性加固、可观测性、备份恢复、容器化、测试回归、安全检查和技术交付，使项目达到以下状态：

- 核心搜索链路和文献库链路可稳定运行。
- 单一外部来源或本地组件故障时能够降级。
- Redis 丢失不会破坏长期业务数据。
- FAISS 可以从 SQLite 和模型重新构建。
- Docker Compose 能够启动项目所需服务。
- 项目具备完整安装、运行、排错和恢复文档。
- 形成可用于比赛演示的冻结版本。

本阶段不新增超出首版边界的大型功能。

---

## 2. 前置条件

- 阶段一至阶段六的主要交付物完成。
- 文献搜索和我的文献库两个页面可用。
- 多源检索、排序、核验和多轮搜索已打通。
- 所有数据库迁移可在干净环境执行。
- 已保留 mock 数据和基础 E2E 测试。

## 5. 小阶段 7.2：降级矩阵

| 故障 | 降级行为 | 用户可见信息 |
|---|---|---|
| OpenAlex 失败 | 使用 S2 + 动态来源 | 标记 OpenAlex 不可用 |
| Semantic Scholar 失败 | 继续其他来源，引用补充减少 | 标记引用信息可能不完整 |
| 动态第三源失败 | 使用双核心来源 | 标记领域来源降级 |
| Redis 失败 | 绕过缓存、使用本地限流和 SQLite 快照 | 响应可能变慢 |
| FAISS 失败 | 使用 RRF、规则和 reranker 小集合 | 语义粗排已降级 |
| BGE-M3 失败 | 跳过向量粗排并收紧候选上限 | 语义检索不可用 |
| reranker 失败 | 使用 BGE 排名 | 精细重排不可用 |
| DeepSeek Flash 失败 | 按预算尝试 Pro 或返回未核验结果 | 条件核验不完整 |
| DeepSeek Pro 失败 | 使用 Flash 当前结果 | 高级回退不可用 |
| SQLite 写失败 | 当前请求失败，禁止只保存在 Redis | 数据未持久化 |
| SSE 失败 | 前端轮询状态 API | 实时进度降级 |

降级不能掩盖错误，必须在结果、日志和 usage 中明确记录。

## 6. 小阶段 7.3：运行状态机

统一搜索状态：

```text
queued
running
partial
completed
failed
cancelled
interrupted
```

状态转换必须合法，例如：

```text
queued → running
running → completed | partial | failed | cancelled | interrupted
interrupted → running | failed
```

不能从 completed 回到 running；重试应创建新 run 或明确记录 parent_run_id。

1. 获取 active paper。
2. 检查 embedding 缓存。

### 15.7 独立离线评测测试

第一阶段离线评测代码位于仓库根目录 `evaluation/`，不挂接生产 FastAPI、LangGraph 或搜索服务。其测试只使用纯合成 fixture，并覆盖：

- JSONL 契约和五类候选数量参数的独立语义；
- DOI、arXiv、PMID 与平台标识规范化、保守匹配和去重；
- P/R/F1、Micro/Macro、MRR 与二元 nDCG；
- 缺失预测、重复预测和缺失效率观测；
- 明确标注为非官方的效率、结构与综合代理分；
- JSON、JSONL 与 Markdown 报告输出。

第二阶段在同一独立目录中增加：

- `pre_semantic_ranking` 排序前候选快照契约和 SHA-256 内容封存，边界固定为身份去重、RRF 与确定性规则过滤后、BGE-M3 前；
- UTF-8 JSONL 只读加载、重复查询、重复论文、阶段数量和哈希篡改校验；
- 共享 `source_recall_count` 与 `evaluation_top_k` 的 A/B/C/D 消融矩阵；
- 不绑定模型库的 BGE-M3/Cross Encoder 打分协议，以及只通过显式注入替身或未来适配器运行的离线编排；
- 计划级 `academic_api_calls=0`、`deepseek_calls=0` 审计字段；
- 各阶段输入数、输出数、候选上限、模型名、设备、批大小、耗时和 OOM 重试记录。

快照分别记录成功映射、身份去重后、规则过滤和实际排序输入数量；未观测到供应商原始响应条目数时 `raw_candidate_count` 保持空值，不得用统一 `PaperRecord` 数量伪装。现有 SQLite 搜索结果是生产排序后的最终结果快照，不能作为上述排序前候选快照。第二阶段不增加生产导出接口，也不自动加载本地模型。

第三阶段的生产内部边界和显式快照导出已完成：`CandidateGenerationService` 统一负责来源路由与调用、已规范化 `PaperRecord` 汇总、身份融合/RRF、确定性规则过滤和独立网页发现，并返回分别统计学术来源与网页来源的 `CandidateGenerationResult`。`MultiSourceRecallCoordinator` 在该结果上继续执行原有 BGE-M3、Cross Encoder、DeepSeek 和覆盖分析，公共 FastAPI 响应字段与默认行为不变。候选生成服务自身不构造、不加载也不调用任何排序模型或 LLM；其测试只使用来源替身。

`python -m evaluation snapshot-export` 是唯一受控在线评测入口。它要求用户提供已准备好的第一轮 `QueryIntent`、明确的 `source_recall_count`、新输出路径和 `--allow-online-sources`，并拒绝网页发现、BGE-M3、Cross Encoder 和已有输出。命令在授权和静态预检完成后才延迟装配生产候选服务，只执行一次候选生成并写出一份 SHA-256 封存的 JSONL；不调用 Query Agent、DeepSeek、覆盖分析或多轮工作流。Codex 不自动执行该命令，真实学术 API 仍由用户显式运行。

执行命令为 `pytest evaluation/tests -q`。候选快照可用 `python -m evaluation snapshot-check` 只读校验，A/B/C/D 可用 `python -m evaluation ablation-plan` 生成零 API、零 DeepSeek 的任务计划；这两个命令和 `fixture` 均不得下载真实数据、访问 API、运行 LLM 或加载本地排序模型。只有上述带显式授权的 `snapshot-export` 可以访问学术来源。真实 benchmark 仍由用户显式执行。

第四阶段新增 `python -m evaluation dataset-gold-import`，用于把用户已准备的本地公开数据集查询和相关论文集合转换为 `GoldQuery` JSONL。它要求用户显式给出数据集、切分、输入与新输出路径，拒绝重复查询、重复相关论文、保留元数据冲突和覆盖已有结果；不读取 `.env`，不下载或自动解析 PaSa、RealScholarQuery 等第三方原始文件，也不调用学术 API、LLM 或模型。若需原生数据集格式适配，必须由用户提供确认的版本字段说明或脱敏样例后单独实现。

为支持用户准备 PaSa 原始数据，仓库提供 `scripts/download_pasa_dataset.py`。该脚本只在用户手动运行后通过 `huggingface_hub.snapshot_download` 请求 gated 数据集 `CarlanLark/pasa-dataset`，强制使用本机 `hf auth login` 已保存认证，代码不保存 Token。默认 `allow_patterns` 仅为 `AutoScholarQuery/dev.jsonl`，可显式选择 `RealScholarQuery/test.jsonl` 和 `paper_database/id2paper.json`，不会下载整个仓库；默认输出是受 Git 忽略的 `data/evaluation/pasa/`。脚本对未接受条款、未登录、网络失败、版本或文件不存在提供安全错误提示，完成后仅打印文件路径和大小。Codex 不自动执行该脚本。

用户已下载的 `AutoScholarQuery/dev.jsonl` 现可通过 `python -m evaluation pasa-gold-import --split auto-dev` 纯本地转换为 `GoldQuery`。适配器只接受已确认的 `qid`、`question`、`answer`、`answer_arxiv_id` 和 `source_meta` 字段，严格按索引配对标题与 arXiv ID；若 PaSa 原始标注按统一身份规则重复，则保留首次论文并将移除数量写入 `pasa_duplicate_answer_count`，同时把来源标量元数据加命名空间后写入输出。此例外不改变通用准备数据导入拒绝重复金标的边界；适配器不读取论文数据库补全内容、不访问任何服务，且输出不能覆盖已有金标。当前未验证 `RealScholarQuery/test.jsonl` 原始字段，不得复用该解析器或将其标记为兼容。

完整 PaSa 开发集当前有 1,000 条 `GoldQuery`，而开发集排序消融固定使用的 20 条必须由 `python -m evaluation gold-subset-select` 从该完整文件确定性封存。命令要求用户显式给出 `--count`、`--selection-id`、`--seed`、新的子集 JSONL 与新的 manifest JSON；manifest 冻结 `sha256-query-id-v1` 策略、输入/输出 SHA-256 和按选择排名排列的完整 `query_id` 列表。它只读取本地金标、不读取 `.env`、不调用模型或服务，且两个输出均不得覆盖已有文件。后续为这些查询生成候选快照仍必须逐条由用户显式使用 `snapshot-export --allow-online-sources` 授权。

## 18. 小阶段 7.15：安全加固

- LLM 只能输出候选白名单 ID。

### 18.4 Web

- 安全 Header。
- 外部链接协议校验。

## 25. 阶段验收条件

- 单一外部来源失败不会使整个搜索失败。
- Redis 不可用时系统可降级运行。
- FAISS、BGE 或 reranker 失败时仍能返回明确标记的结果。
- SQLite 备份和恢复流程通过用户验证。
- FAISS 可从 SQLite 重建。
- Docker Compose 能在干净环境启动。
- 搜索到收藏再到文献库语义搜索的完整链路可用。
- 日志和运行报告能够定位每个阶段的耗时与错误。
- 测试默认不消耗真实 API 和 LLM 额度。
- 项目中不存在真实密钥、未授权全文和本地绝对路径。
- Windows 和 Linux 的 UTF-8 场景均有验证说明。
- README、配置样例和实际命令保持一致。
- 项目范围已冻结，不再引入非首版功能。

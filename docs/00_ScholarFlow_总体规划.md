# ScholarFlow 总体技术规划

## 1. 项目名称

**ScholarFlow**

中文名称：**学流：面向复杂科研查询的智能论文搜索与推荐系统**

## 2. 技术目标

ScholarFlow 接收中文、英文或中英混合的复杂科研查询，将其转换为结构化检索意图，并通过多源学术 API、语义模型和大语言模型完成以下链路：

```text
复杂查询
→ QueryIntent
→ 多源检索
→ 论文规范化
→ 身份解析与版本族合并
→ 规则过滤与 RRF
→ BGE-M3 粗排
→ bge-reranker-v2-m3 重排
→ DeepSeek 条件核验
→ 覆盖缺口分析与多轮搜索
→ 最终约 20 篇论文
→ 保存到我的文献库
```

系统不是单次关键词搜索，也不采用“把大量论文直接交给 LLM 排序”的方式。

## 3. 首版技术边界

### 3.1 必须实现

- 复杂查询结构化解析。
- OpenAlex 与 Semantic Scholar 核心检索。
- arXiv、PubMed、DBLP 动态第三来源。
- 多来源限流、缓存、重试、熔断和降级。
- DOI、平台 ID、标题、作者和版本族处理。
- RRF 多源融合。
- BGE-M3 本地嵌入与 FAISS 索引。
- bge-reranker-v2-m3 本地重排。
- DeepSeek-V4-Flash 默认调用和 DeepSeek-V4-Pro 回退。
- 多轮检索、覆盖缺口分析和保护性停止条件。
- Redis、SQLite、FAISS 分层存储。
- 文献搜索和我的文献库两个前端一级模块。
- REST、SSE、日志、用量记录、备份与恢复工具。

### 3.2 首版不实现

- PDF 全文阅读和全文问答。
- 每日论文推荐和邮件订阅。
- 多用户、组织权限和在线协作。
- 模型微调、强化学习或学习排序训练。
- 分布式向量数据库。
- 公开数据集评测系统。
- 未授权论文全文抓取与分发。

## 4. 固定技术栈

| 层级 | 技术 |
|---|---|
| 前端 | Vue 3、TypeScript、Vite、Ant Design Vue、ECharts |
| 后端 | Python 3.11+、FastAPI、Pydantic |
| 编排 | LangGraph |
| LLM | DeepSeek-V4-Flash、DeepSeek-V4-Pro |
| 嵌入 | BGE-M3 |
| 重排 | bge-reranker-v2-m3 |
| 缓存与运行状态 | Redis |
| 长期数据 | SQLite |
| 向量索引 | FAISS |
| 部署 | Docker Compose |
| 交互 | REST + SSE |

## 5. 核心领域对象

### QueryIntent

至少包含：

- 原始查询、规范化查询、查询语言。
- 主题、方法、任务、数据集、领域。
- 作者、机构、venue、论文类型。
- 年份范围。
- `must_include`、`should_include`、`exclude`。
- 子查询、搜索目的和查询优先级。
- 目标结果数，默认 20。
- 查询复杂度和领域分类。

### PaperRecord

至少包含：

- 内部 `paper_id`。
- 标题、摘要、关键词、年份、venue、论文类型。
- 作者和作者平台 ID。
- DOI、OpenAlex ID、Semantic Scholar ID、arXiv ID、PMID、DBLP key。
- 开放获取状态和合法入口。
- 来源、来源原始排名、命中子查询。
- 版本族 ID。
- 引用、被引、相似和版本关系。
- 向量版本、文本哈希和更新时间。

### SearchRunState

至少包含：

- QueryIntent。
- 当前轮次和已执行子查询。
- 已选来源、原始候选、规范化候选、最终候选。
- 排序和核验结果。
- 覆盖缺口。
- API、Token、费用、耗时和缓存命中。
- 错误、降级来源和停止原因。

## 6. 搜索与排序原则

### 6.1 搜索目标

- 多轮检索，最终返回约 20 篇满足条件的论文。
- 相关性优先。
- 用户指定的时间范围属于硬约束。
- 在相关性相近时优先近期论文。
- 引用量和来源质量只能作为次级因素。
- 不允许无限搜索。

### 6.2 停止条件

满足任一条件时停止：

- 已获得约 20 篇符合要求的论文。
- 用户关键约束已充分覆盖。
- 新一轮没有新增有效论文。
- 达到最大轮数、API、Token、费用或时间预算。
- 外部来源持续失败。

所有阈值必须配置化。

### 6.3 排序链路

```text
规则过滤
→ RRF 多源融合
→ BGE-M3 粗排
→ bge-reranker-v2-m3 重排
→ DeepSeek 条件核验
→ 相关性接近时进行时效性和多样化调整
```

## 7. 数据职责

### Redis

- API 搜索结果缓存。
- 论文详情缓存。
- QueryIntent 与搜索计划缓存。
- LangGraph 运行状态。
- SSE 事件。
- 限流计数、请求锁和失败负缓存。

### SQLite

- 论文事实、标识符、作者和来源。
- 引用和版本关系。
- 搜索历史、运行快照和最终结果。
- 文献库、标签和备注。
- API、LLM、Prompt 和工作流用量记录。
- 向量元数据与索引元数据。

### FAISS

- 全局论文向量索引。
- 我的文献库向量索引。
- 仅保存可重建向量索引，不保存完整业务事实。

## 8. 大阶段划分

| 阶段 | 名称 | 主要输出 |
|---|---|---|
| 阶段一 | 工程基础与数据基线 | 可启动的前后端骨架、配置、日志、Redis/SQLite/FAISS 基础 |
| 阶段二 | 多源学术检索 | 统一适配器、三源动态路由、缓存限流与降级 |
| 阶段三 | 查询理解与工作流编排 | QueryIntent、模型路由、LangGraph 主流程、SSE 事件 |
| 阶段四 | 规范化去重与多源融合 | PaperRecord、身份解析、版本族、RRF、持久化 |
| 阶段五 | 语义排序与智能核验 | BGE-M3、FAISS、reranker、LLM 核验、多轮搜索 |
| 阶段六 | 后端接口与前端应用 | 搜索页、文献库、对比、引文图、技术路线 |
| 阶段七 | 系统集成与交付 | 可靠性、备份恢复、Docker、回归测试、文档 |

## 9. 阶段依赖

```text
阶段一
  ↓
阶段二
  ↓
阶段三
  ↓
阶段四
  ↓
阶段五
  ↓
阶段六
  ↓
阶段七
```

允许在阶段三完成核心 Schema 后，并行开发阶段四的部分 Repository 与阶段六的前端静态页面，但不得跳过依赖直接实现完整业务闭环。

## 10. 全局工程要求

- 新增 Python 依赖时同步更新带版本号的 `requirements.txt`。
- 新增前端依赖时同步更新 `package.json` 和锁文件。
- 代码、配置和文档统一 UTF-8。
- 密钥只通过环境变量或 Secret 注入。
- 日志同时输出控制台和文件，错误必须记录堆栈。
- 外部 API 测试优先使用 mock 或录制响应。
- 所有易变化模型名、阈值、API 频率、候选规模和预算都配置化。
- 每阶段完成后更新相关技术文档，不依赖对话历史保存设计决策。

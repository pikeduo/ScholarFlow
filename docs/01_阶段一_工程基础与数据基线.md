# 阶段一：工程基础与数据基线

## 1. 阶段目标

本阶段建立 ScholarFlow 的工程骨架、配置体系、日志体系、基础数据层和前后端启动链路。完成后，项目应具备以下能力：

- 后端能够通过 FastAPI 启动并提供健康检查。
- 前端能够通过 Vue 3 启动并访问两个一级页面的空壳。
- SQLite、Redis、FAISS 均具备独立封装和健康检查。
- 所有配置通过环境变量和配置文件加载。
- 日志同时写入控制台和文件，并能够携带 `run_id` 等上下文。
- 项目已建立测试、编码、依赖和 Git 基线。

本阶段不实现真实学术检索、LangGraph 主流程和模型推理。

---

- Git 仓库已创建。

- Python、Node.js、Redis 和 Git 已安装，具体版本在实际创建项目时写入 README 和依赖文件。

### 3.1 目录边界

- `api/` 只负责协议转换、鉴权、参数校验和返回响应，不实现检索算法。
- `services/` 负责业务编排，不能直接依赖 FastAPI 请求对象。
- `adapters/` 隔离外部 API 字段和调用规则。
- `repositories/` 只负责数据访问，不进行排序和搜索决策。
- `workflows/` 只依赖领域模型和 service 接口。
- `vector/` 隔离本地模型和 FAISS 的实现细节。
- `core/` 不依赖具体业务模块，避免循环引用。

## 4. 小阶段 1.1：后端项目初始化

### 4.1 技术选择

建议使用：

- FastAPI：HTTP API。
- Pydantic v2：请求、响应和配置校验。
- Pydantic Settings：环境变量加载。
- SQLAlchemy 2.x：SQLite ORM 和事务。
- Alembic：数据库迁移。
- `redis.asyncio`：异步 Redis 客户端。
- `httpx`：后续外部 API 异步请求。
- pytest：测试框架。

具体版本由 Codex 在实现时选择当前兼容版本，并固定写入 `backend/requirements.txt`。

### 4.2 应用工厂

建议实现：

```python
# backend/app/main.py

def create_app() -> FastAPI:
    """创建并配置 FastAPI 应用。"""
```

应用工厂负责：

- 加载配置。
- 注册生命周期函数。
- 注册路由。
- 注册异常处理器。
- 注册 CORS。
- 注册请求日志中间件。
- 设置 OpenAPI 元数据。

禁止在模块导入阶段连接 Redis、加载模型或执行数据库迁移。

### 4.3 生命周期

使用 FastAPI lifespan 管理：

1. 加载配置。
2. 初始化日志。
3. 初始化 SQLite Engine 和 Session Factory。
4. 检查 Redis。
5. 加载 FAISS 索引元数据，不加载 BGE-M3。
6. 启动完成后输出阶段日志。
7. 关闭时释放 Redis、数据库和 HTTP 客户端。

## 5. 小阶段 1.2：配置系统

### 5.1 配置层级

推荐优先级：

```text
默认值
< YAML/TOML 配置
< .env
< 操作系统环境变量
< 启动参数
```

### 5.2 配置对象

建议拆分：

```python
class AppSettings(BaseSettings): ...
class DatabaseSettings(BaseModel): ...
class RedisSettings(BaseModel): ...
class LoggingSettings(BaseModel): ...
class SearchSettings(BaseModel): ...
class ModelSettings(BaseModel): ...
class ApiSourceSettings(BaseModel): ...
```

### 5.3 基础配置示例

```yaml
app:
  name: ScholarFlow
  environment: development
  api_prefix: /api/v1

search:
  target_count: 20
  max_rounds: 3
  max_candidates: 300
  bge_keep: 60
  reranker_keep: 40
  llm_verify_keep: 30

storage:
  sqlite_url: sqlite+aiosqlite:///data/sqlite/scholarflow.db
  redis_url: redis://localhost:6379/0
  faiss_dir: data/faiss

logging:
  level: INFO
  directory: data/logs
  json_file: true
```

### 5.4 配置校验

启动时必须检查：

- `target_count > 0`。
- `bge_keep >= reranker_keep >= target_count`。
- Redis URL 合法。
- 数据目录可写。
- 生产环境不允许使用示例密钥。
- 必需的密钥未提供时，仅禁用对应能力，不得打印密钥值。

### 6.1 日志输出

至少提供：

建议字段：


### 6.2 上下文传递

使用 `contextvars` 保存：

- `request_id`
- `run_id`
- 当前工作流节点
- 当前学术来源

API 请求进入时生成 `request_id`，搜索任务创建后增加 `run_id`。

### 6.3 异常层级

建议定义：

```python
class ScholarFlowError(Exception): ...
class ConfigurationError(ScholarFlowError): ...
class StorageError(ScholarFlowError): ...
class ExternalServiceError(ScholarFlowError): ...
class RateLimitError(ExternalServiceError): ...
class ModelError(ScholarFlowError): ...
class WorkflowError(ScholarFlowError): ...
```

异常应包含：

- 可公开错误码。
- 内部错误信息。
- 是否可重试。
- HTTP 状态码。
- 上游来源。

### 6.4 日志禁止项

禁止记录：

- API Key。
- Access Token。
- `.env` 内容。
- 完整模型请求中的敏感数据。
- 过大的外部响应。

## 7. 小阶段 1.4：SQLite 技术实现

### 7.1 ORM 与连接

推荐：

- SQLAlchemy 2.x Async Engine。
- `aiosqlite` 驱动。
- WAL 模式。
- 外键约束开启。
- Repository 使用显式事务。

初始化 SQL：

```sql
PRAGMA journal_mode=WAL;
PRAGMA foreign_keys=ON;
PRAGMA synchronous=NORMAL;
PRAGMA busy_timeout=5000;
```

### 7.2 基础表

本阶段先创建最小但可扩展的表：

```text
papers
paper_identifiers
paper_sources
authors
paper_authors
search_sessions
workflow_runs
workflow_node_runs
api_usage
llm_usage
embedding_records
index_metadata
library_items
tags
library_item_tags
```

### 7.3 Repository 接口

建议定义：

```python
class PaperRepository(Protocol):
    async def get_by_id(self, paper_id: str): ...
    async def upsert_many(self, papers: list[PaperRecord]): ...

class SearchRunRepository(Protocol):
    async def create_run(self, run: SearchRun): ...
    async def update_status(self, run_id: str, status: str): ...
```

本阶段可使用占位领域模型，阶段四再扩充完整字段。

### 7.4 Alembic

要求：

- 任何表结构变化必须创建迁移。
- 不允许在应用启动时隐式删除或重建数据库。
- `scripts/init_database.py` 只负责执行迁移和基础检查。

## 8. 小阶段 1.5：Redis 技术实现

### 8.1 Redis Client Manager

提供：

```python
class RedisManager:
    async def connect(self): ...
    async def close(self): ...
    async def health_check(self) -> bool: ...
```

### 8.2 Key 规范

```text
ScholarFlow:source:cache:<source>:<operation>:<version>:<hash>
ScholarFlow:run:state:<run_id>
ScholarFlow:sse:stream:<run_id>
ScholarFlow:source:rate:<source>:<window>
ScholarFlow:lock:resource:<resource_hash>
ScholarFlow:source:negative:<source>:<hash>
```

### 8.3 序列化

- 统一 UTF-8 JSON。
- 结构中保存版本号。
- 大对象压缩应延后，先控制缓存内容大小。
- 禁止使用不可信 pickle。

### 8.4 降级

Redis 不可用时：

- API 请求仍可继续。
- 缓存、锁和限流能力进入降级模式。
- 发出 WARNING 日志。
- 运行状态关键快照仍写 SQLite。

## 9. 小阶段 1.6：FAISS 基础实现

### 9.1 索引类型

首版使用：

```text
IndexIDMap2(IndexFlatIP)
```

要求输入向量先做 L2 归一化，使内积等价于余弦相似度。

### 9.2 IndexManager

建议接口：

```python
class FaissIndexManager:
    def create(self, dimension: int): ...
    def load(self, path: Path): ...
    def save(self, path: Path): ...
    def add(self, vector_ids, vectors): ...
    def search(self, query_vectors, top_k: int): ...
    def rebuild(self, records): ...
```

### 9.3 索引元数据

SQLite `index_metadata` 保存：

- 索引名称。
- 文件路径。
- 向量维度。
- 模型名称和版本。
- 文本构造版本。
- 当前向量数。
- 创建和更新时间。

本阶段使用随机向量或 fixture 验证，不下载 BGE-M3。

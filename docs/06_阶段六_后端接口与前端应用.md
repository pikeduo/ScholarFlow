# 阶段六：后端接口与前端应用

> 实施补充：搜索页统一使用最多两轮的标准检索，并默认执行 DeepSeek 核验；用户可分别选择 BGE-M3 语义粗排和 Cross Encoder 重排，二者默认关闭，开启任一项都必须明确提示会显著增加搜索耗时。来自 `/api/v1/usage/{run_id}` 的 `latency_ms` 保持后端毫秒契约，前端按未满一秒、秒、分钟自动进位展示。

## 1. 阶段目标

本阶段将已完成的搜索工作流和文献库能力封装为稳定后端 API，并实现 Vue 3 前端。首版仅保留两个一级模块：

1. 文献搜索。
2. 我的文献库。

完成后，用户应能够输入复杂科研查询、编辑 QueryIntent、查看多轮搜索过程、浏览证据化论文结果、保存论文、管理文献库并进行语义搜索。

多轮检索最多执行三轮。每轮只调用一个按核心优先级和领域相关性排序的学术来源，避免同一运行对 Semantic Scholar 等受限来源重复请求；前两轮通过不同来源与子查询补足约束。若两轮后高相关论文仍未达到目标，第三轮优先切换到此前未调用的第三个领域相关学术来源。没有第三候选时，复用最相关的已选来源，并把该来源的候选返回上限收缩为尚缺的高相关论文数；此内部轮次字段不暴露给前端编辑器。

本地 BGE-M3 与 Cross Encoder 共享 `SCHOLARFLOW_LOCAL_MODEL_DEVICE` 设备策略：`auto` 在 CUDA 可用且总显存达到 `SCHOLARFLOW_LOCAL_MODEL_MINIMUM_CUDA_MEMORY_MB` 时使用 CUDA，否则安全回退 CPU；`cuda` 用于明确要求 GPU 的部署。两个模型在 CUDA 上自动使用 FP16，模型加载日志必须记录实际设备。

- 阶段五搜索闭环可通过 Application Service 调用。
- QueryIntent、PaperRecord、VerificationResult 和 SearchRunState 字段稳定。
- SQLite、Redis、FAISS 均可用。

## 3. 前后端交互架构

```text
Vue 3
  ├─ REST：提交、状态、结果、详情、文献库
  └─ SSE：搜索进度、警告、完成事件
       ↓
FastAPI API Layer
       ↓
Application Services
       ↓
LangGraph / Repositories / FAISS
```

原则：

- SSE 只传输进度，不作为最终事实源。
- 最终结果通过 REST 获取。
- 前端不直接调用学术 API 或 DeepSeek。
- API 返回统一错误结构和 `request_id`。

## 5. 小阶段 6.2：搜索提交 API

### `POST /api/v1/search`

请求：

```json
{
  "query": "查找近五年使用大语言模型进行时间序列预测并在 ETT 上实验的论文，排除综述",
  "search_mode": "standard",
  "target_count": 20,
  "filters": {
    "year_start": 2021,
    "year_end": 2026
  }
}
```

响应：

```json
{
  "run_id": "...",
  "status": "queued",
  "events_url": "/api/v1/search/.../events",
  "status_url": "/api/v1/search/..."
}
```

实现要求：

- 参数校验后立即创建 `run_id`。
- 写 SQLite search session。
- 启动后台工作流。
- 目标在较短时间内返回，不等待搜索完成。
- 相同运行中请求可按幂等键复用或明确创建新任务，策略配置化。


- 报告中的结论必须可追溯到响应字段；不得将自由生成文本伪装成论文事实。前端在新搜索或恢复完成结果后异步加载，读取失败不得阻塞论文列表。

## 9. 小阶段 6.6：论文详情 API

### `GET /api/v1/papers/detail?paper_id=<paper_id>`

返回：

- canonical 论文信息。
- 所有标识符。
- 来源。
- 版本族。
- 合法开放链接。
- 引用和被引摘要。
- 技术路线标签。
- 是否收藏。

详情读取 SQLite，不在每次页面打开时实时调用所有外部来源。

论文标识通过查询参数传递，以兼容 OpenAlex URL 等包含斜杠的来源标识；旧的无斜杠路径仅保留内部兼容，不再供前端使用。

`references` 仅表示当前论文引用的上游论文在原始来源中的标识；它不是用户“我的文献库”的收藏记录。详情页可通过字段级翻译接口分别按需翻译标题和摘要。

前端应将已校验 DOI 规范化为固定 `https://doi.org/<DOI>` 新标签链接；论文标题和详情页主访问入口均只跳转 DOI 落地页。DOI 缺失时标题保持纯文本，详情页不展示主访问入口。若来源提供的 `open_access_url` 明确指向 HTTP(S) PDF，可额外展示独立“打开公开 PDF”按钮；不抓取或分发受限全文。

### `POST /api/v1/papers/translation/{field}`

参数：

- `field`：仅允许 `title` 或 `abstract`。
- `paper_id`：查询参数，必须对应已保存搜索结果中的论文。

规则：

- 只翻译用户点击的单一字段，标题与摘要请求和界面加载状态必须独立。
- 前端不得提交标题或摘要正文，也不得持有模型密钥。
- 译文以论文标识、字段和原文 SHA-256 哈希写入 SQLite；相同原文跨浏览器复用，原文变化时自动失效。
- 缓存不可用时允许本次请求直接调用翻译适配器，但不得返回内部存储错误。

## 13. 小阶段 6.10：文献库 API

### 列表

```text
GET /api/v1/library/items
```

支持：

- 可点击关键词筛选：聚合用户维护关键词和论文来源关键词，关键词区限高并可滚动。
- 年份。
- venue。
- 阅读状态。
- 关键词。
- `updated_desc`、年份升降序和标题升序排序。
- `page`、`page_size` 服务端分页；响应返回 `total`、`page`、`page_size` 和 `total_pages`。

年份与 venue 条件同样作用于语义检索候选范围；关键词面板保留当前结构化范围内的完整聚合结果，不受当前关键词或当前页面截断影响。

### 收藏

```text
POST /api/v1/library/items
```

请求：

- paper_id。
- keywords。

过渡期内，保存和更新请求仍接受旧 `tags` 字段，响应也保留同内容的废弃 `tags` 镜像；前端和新增调用必须使用 `keywords`。
- note。
- reading_status。

规则：

- 同一 paper_id 不重复收藏。
- 收藏只建立关联，不复制完整论文事实。
- 收藏只写入 SQLite；首次执行文献库语义检索前才按当前候选补齐或复用 FAISS 索引，避免收藏等待 BGE-M3 模型加载。

### 更新

```text
PATCH /api/v1/library/items/{id}
```

更新：

- note。
- reading_status。
- keywords。
- 用户技术路线修正。

### 删除

```text
DELETE /api/v1/library/items/{id}
```

删除收藏关系，不删除全局 PaperRecord。

### 语义搜索

```text
GET /api/v1/library/items/semantic-search
```

使用 BGE-M3 + 文献库 FAISS，并支持结构化过滤。

## 21. 小阶段 6.18：前端容错

- SSE 断线自动重连，使用 Last-Event-ID。
- SSE 多次失败后回退状态轮询。
- 搜索部分完成时仍展示结果和警告。
- API 429 显示可重试提示。
- 空结果说明可能缺失的条件，不显示空白页。
- 组件卸载时关闭 SSE。
- 前端刷新后根据 URL 中 run_id 恢复。

## 22. 小阶段 6.19：安全

- Key 不进入前端构建变量。
- 外部标题和摘要按文本渲染，禁止直接注入 HTML。
- 链接只允许 http/https 并进行安全属性设置。
- 输入长度和批量选择数量限制。
- 后端重新校验所有 paper_id。
- 不信任前端传入的相关性和分数。

# 阶段六：后端接口与前端应用

> 实施补充：搜索页标准模式须明确为“DeepSeek 核验、跳过 BGE-M3/Cross Encoder”的快速路径；深度模式须警告会加载两类本地排序模型并明显增加耗时。来自 `/api/v1/usage/{run_id}` 的 `latency_ms` 保持后端毫秒契约，前端按未满一秒、秒、分钟自动进位展示。

## 1. 阶段目标

本阶段将已完成的搜索工作流和文献库能力封装为稳定后端 API，并实现 Vue 3 前端。首版仅保留两个一级模块：

1. 文献搜索。
2. 我的文献库。

完成后，用户应能够输入复杂科研查询、编辑 QueryIntent、查看多轮搜索过程、浏览证据化论文结果、保存论文、管理文献库并进行语义搜索。

---

## 2. 前置条件

- 阶段五搜索闭环可通过 Application Service 调用。
- QueryIntent、PaperRecord、VerificationResult 和 SearchRunState 字段稳定。
- SQLite、Redis、FAISS 均可用。
- SSE 事件模型已定义。

---

## 3. 前后端交互架构

```text
Vue 3
  ├─ REST：提交、状态、结果、详情、文献库
  └─ SSE：搜索进度、警告、完成事件
       ↓
FastAPI API Layer
       ↓
Application Services
       ↓
LangGraph / Repositories / FAISS
```

原则：

- SSE 只传输进度，不作为最终事实源。
- 最终结果通过 REST 获取。
- 前端不直接调用学术 API 或 DeepSeek。
- API 返回统一错误结构和 `request_id`。

## 5. 小阶段 6.2：搜索提交 API

### `POST /api/v1/search`

请求：

```json
{
  "query": "查找近五年使用大语言模型进行时间序列预测并在 ETT 上实验的论文，排除综述",
  "search_mode": "standard",
  "target_count": 20,
  "filters": {
    "year_start": 2021,
    "year_end": 2026
  }
}
```

响应：

```json
{
  "run_id": "...",
  "status": "queued",
  "events_url": "/api/v1/search/.../events",
  "status_url": "/api/v1/search/..."
}
```

实现要求：

- 参数校验后立即创建 `run_id`。
- 写 SQLite search session。
- 启动后台工作流。
- 目标在较短时间内返回，不等待搜索完成。
- 相同运行中请求可按幂等键复用或明确创建新任务，策略配置化。

## 6. 小阶段 6.3：搜索状态 API

### `GET /api/v1/search/{run_id}`

返回：

- 状态：queued/running/completed/partial/failed/cancelled。
- 当前节点。
- 当前轮次。
- QueryIntent。
- 来源状态。
- 候选数量统计。
- 预算使用。
- 警告。
- 停止原因。

前端轮询只作为 SSE 失效时的备用方案。

## 7. 小阶段 6.4：SSE API

### `GET /api/v1/search/{run_id}/events`

### 7.1 协议

```text
id: <event_id>
event: progress
data: <json>
```

### 7.2 实现

- 支持 `Last-Event-ID`。
- 每 15–30 秒发送心跳，值配置化。
- Redis 保存短期事件。
- 订阅开始时补发未读事件。
- 任务完成后发送 `completed` 并关闭。
- 连接断开不取消后端任务。

### 7.3 事件数据

```json
{
  "run_id": "...",
  "node": "semantic_rank",
  "round": 2,
  "message": "语义粗排完成",
  "metrics": {
    "input_count": 137,
    "output_count": 60
  }
}
```

不返回内部推理链和完整 Prompt。

## 8. 小阶段 6.5：搜索结果 API

### `GET /api/v1/search/{run_id}/results`

查询参数：

- page。
- page_size。
- relevance_level。
- year_start/year_end。
- source。
- venue。
- route。
- must_satisfied。
- sort。

结果项：

```python
class PaperSearchResultResponse(BaseModel):
    paper: PaperSummaryResponse
    relevance_level: str
    final_score: float
    score_breakdown: ScoreBreakdownResponse
    constraint_matrix: list[ConstraintEvidenceResponse]
    recommendation_reason: str
    sources: list[SourceBadgeResponse]
    versions: list[PaperVersionResponse]
    saved_to_library: bool
```

默认排序为系统相关性，用户可切换年份和引用排序。

## 9. 小阶段 6.6：论文详情 API

### `GET /api/v1/papers/{paper_id}`

返回：

- canonical 论文信息。
- 所有标识符。
- 来源。
- 版本族。
- 合法开放链接。
- 引用和被引摘要。
- 技术路线标签。
- 是否收藏。

详情读取 SQLite，不在每次页面打开时实时调用所有外部来源。

## 10. 小阶段 6.7：论文比较 API

### `POST /api/v1/compare`

请求选择 2–5 个 `paper_id`。

对比字段：

- 研究问题。
- 方法。
- 数据集。
- 实验设置。
- 关键贡献。
- 局限。
- 条件满足情况。
- 证据来源。

实现：

- 优先复用已有核验结果。
- 缺失结构字段时可调用 Flash 对小集合整理。
- 输出必须绑定论文 ID 和证据。
- 不读取 PDF 全文。

---

## 11. 小阶段 6.8：引文图 API

### `GET /api/v1/graph/citations`

参数：

- paper_ids。
- max_nodes。
- edge_types。
- depth。

节点：

- paper_id。
- 标题。
- 年份。
- relevance。
- route。

边类型：

- `cites`
- `cited_by`
- `same_work`
- `extended_version`
- `semantic_similar`

要求：

- 引用边只来自 API 或数据库事实。
- 语义边明确标注置信度。
- 默认最多 30–50 节点。
- 超过限制时按相关性和用户选择裁剪。

## 12. 小阶段 6.9：技术路线 API

### `GET /api/v1/routes`

输入搜索 `run_id` 或文献库过滤条件。

输出：

```python
class TechnicalRouteResponse(BaseModel):
    route_id: str
    name: str
    summary: str
    common_methods: list[str]
    differences: list[str]
    representative_paper_ids: list[str]
    paper_ids: list[str]

```

路线只对最终小集合生成，避免对大量候选分类。

## 13. 小阶段 6.10：文献库 API

### 列表

```text
GET /api/v1/library
```

支持：

- 标签。
- 年份。
- venue。
- 阅读状态。
- 技术路线。
- 关键词。

### 收藏

```text
POST /api/v1/library/items
```

请求：

- paper_id。
- tags。
- note。
- reading_status。

规则：

- 同一 paper_id 不重复收藏。
- 收藏只建立关联，不复制完整论文事实。
- 收藏后更新文献库 FAISS 索引。

### 更新

```text
PATCH /api/v1/library/items/{id}
```

更新：

- note。
- reading_status。
- tags。
- 用户技术路线修正。

### 删除

```text
DELETE /api/v1/library/items/{id}
```

删除收藏关系，不删除全局 PaperRecord。

### 语义搜索

```text
POST /api/v1/library/search
```

使用 BGE-M3 + 文献库 FAISS，并支持结构化过滤。

## 14. 小阶段 6.11：Usage API

### `GET /api/v1/usage/{run_id}`

## 21. 小阶段 6.18：前端容错

- SSE 断线自动重连，使用 Last-Event-ID。
- SSE 多次失败后回退状态轮询。
- 搜索部分完成时仍展示结果和警告。
- API 429 显示可重试提示。
- 空结果说明可能缺失的条件，不显示空白页。
- 组件卸载时关闭 SSE。
- 前端刷新后根据 URL 中 run_id 恢复。

---

## 22. 小阶段 6.19：安全

- Key 不进入前端构建变量。
- 外部标题和摘要按文本渲染，禁止直接注入 HTML。
- 链接只允许 http/https 并进行安全属性设置。
- 输入长度和批量选择数量限制。
- 后端重新校验所有 paper_id。
- 不信任前端传入的相关性和分数。

## 25. 阶段验收条件

- 用户可提交复杂查询并立即获得 run_id。
- 搜索过程可通过 SSE 实时显示。
- 刷新页面后可恢复运行状态和结果。
- QueryIntent 可编辑并重新搜索。
- 最终结果显示来源、条件状态、证据和推荐理由。
- 用户可收藏论文并在文献库中语义搜索。
- 删除收藏不会删除全局论文事实。
- 对比、引文图和技术路线只使用可信结果。
- 前端不包含任何外部服务密钥。
- 错误、降级和结果不足均有清晰提示。
